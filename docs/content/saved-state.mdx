These values describe **a sandbox and the portal's operation**. They are not
additional keys to put in a profile or Helm values file. The portal saves intended
configuration, ownership, sharing and supported administrative edits in its
metadata database; the runtime supplies native identity and observed status.

A portal sandbox UUID, its friendly name, Kubernetes object UID and Linux UID
serve different purposes. Select an entry to see who assigns it, whether it can
be edited, and how it relates to the saved profile and live workload. See
[Database and persistence](metadata.md) for database and reconciliation behavior.

## Administrator restriction indicators

The summary above the administrator inventory shows enabled global controls and
counts user and namespace policies, including owners outside the current filter.
Each VM shows only User restrictions, VM restrictions and Namespace restrictions; global controls
are not repeated on every VM. Hover or focus a badge to identify the restriction
and its reason.

Announcements are displayed separately. A namespace network-policy badge means
the administrator configuration is saved; use **Network & security** to verify
its applied status.

## Inventory bookmarks

The inventory view and its filters can be bookmarked in the portal URL. These
parameters describe the view; sandbox configuration continues to live in the
metadata database.

| Parameter | Meaning |
| --- | --- |
| `view=admin` | Administrator inventory; the server still checks the signed-in user's role. |
| `owner=test-user@example.test` | Shared inventory for that owner, subject to existing sharing permissions. |
| `q=release` | Inventory text search, up to 256 characters. |
| `profile=example` | Exact profile ID; an unavailable profile is shown explicitly. |

For example, `?view=admin&q=release&profile=example` restores the administrator
inventory filters. Back and Forward restore prior filters. Search edits keep a
single history entry per typing session, and unrelated query parameters and
section anchors are retained. Hosted portals synchronize the same state with the
host address bar. Changing inventory scope retains the existing confirmation
when terminal sessions are open.
